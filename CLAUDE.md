## Project Overview

PHIVE (Philip Helger Integrative Validation Engine) is a generic business document validation engine. It validates XML documents through a layered "Validation Pyramid" approach using XML Schema (XSD) and Schematron rules. Originally built for Peppol, it now supports many document types.

## Build Commands

```bash
mvn install                    # Build and install all modules
mvn test                       # Run all tests
mvn test -pl phive-xml         # Run tests for a single module
mvn test -pl phive-api -Dtest=ValidationResultListTest  # Run a single test class
```

Requires Java 17+ and Maven 3.9+. Tested on Java 17, 21, and 25.

## Module Architecture

Maven modules, layered bottom-up:

- **phive-bom** — Maven Bill of Materials managing the versions of all phive artefacts (no code; keep its `dependencyManagement` in sync when adding a module)
- **phive-api** — Core interfaces and types: `IValidationSource`, `IValidationExecutor`, `IValidationArtefact`, `ValidationResult`, `ValidationResultList`, `ValidationExecutorSetRegistry`, `VESID`
- **phive-xml** — XML-specific validation executors: `ValidationExecutorXSD`, `ValidationExecutorSchematron`, and `ValidationExecutorPartial` (applies any wrapped executor on XPath-selected parts of a document, e.g. the payload of an SBDH envelope). Supports Schematron engines: XSLT, SchXslt, SchXslt2, Pure
- **phive-result** — Result serialization to JSON (`PhiveJsonHelper`) and XML (`PhiveXMLHelper`)
- **phive-ves-model** — VES (Validation Execution Set) XML data model with JAXB-generated classes (generated from `src/main/resources/schemas/`; a `schematron` element with a `partial` child (`DefaultVESLoaderSchematron`) and the `partialRequires` elements (`VESLoader`/`LoadedVES`, executed after `requires`) are mapped onto `ValidationExecutorPartial`. Changes to `ves-1.0.xsd` get a new RC entry in its version history. `phive-ves-engine` test resources `ves/test4` contain a complete VES chain for a Peppol BIS Invoice inside an SBDH)
- **phive-ves-repo** — Repository management extensions integrating with ph-diver
- **phive-ves-engine** — VES execution engine that loads and runs VES definitions

Dependency flow: `phive-api` → `phive-xml` → `phive-result` → `phive-ves-model` → `phive-ves-engine`. `phive-ves-repo` extends `phive-ves-model`.

## Validation Execution Flow

1. Register `ValidationExecutorSet` instances (identified by `VESID`) in a `ValidationExecutorSetRegistry`
2. Create `ValidationSourceXML` from the document to validate
3. Execute via `ValidationExecutionManager` which runs each layer (XSD, then Schematron rules)
4. Collect `ValidationResultList` containing per-layer results
5. Optionally transform results via `PhiveJsonHelper` or `PhiveXMLHelper`

The pseudo versions `latest-active` / `latest-release-active` select the newest VES whose status `isActivePer` the check date (not deprecated and within the validity period). `VESLoaderPseudoVersionResolver` reads the `deprecated` flag from the JAXB status directly, because `VESStatus1Helper.convert` derives the status type for the current date and reports an expired deprecated VES as `EXPIRED`.

## Key Dependencies

- **ph-commons** (12.7.2-SNAPSHOT, for `ZipWalker` in `ph-io`) — Core utilities, error handling, collections. `DefaultVESLoaderXSD` reads XSD ZIP files with `com.helger.io.zip.ZipWalker`; the limits are the static `setMaxUnzippedSize` / `setMaxZipEntryCount`
- **ph-schematron** (10.3.3) — Schematron validation engines. `ValidationExecutorSchematron` wraps DOM sources in `SaxonDOMSource` (`ph-schematron-saxon`) so Saxon builds a native tree; a plain `DOMSource` makes sibling-axis rules quadratic in document size (issue #37)
- **ph-diver** (4.2.0) — DVR coordinate handling and repository management
- **JAXB 4.0** — XML binding for VES model

## Conventions

- Test framework is JUnit 4 (not JUnit 5)
- Null-safety annotations from JSpecify and javax.annotation (`@NonNull`, `@Nullable`, `@Nonnegative`, `@Nonempty`)
- JAXB classes in `phive-ves-model` are auto-generated by `ph-jaxb-plugin` — do not edit files under generated source directories
- Package root: `com.helger.phive` (sub-packages: `.api`, `.xml`, `.result`, `.ves.model`, `.ves.repo`, `.ves.engine`)
